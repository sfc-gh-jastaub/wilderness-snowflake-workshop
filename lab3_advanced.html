Overview

The situation

Over lunch, Tom Walsh's team set the morning's assistant up as the production copy that 72 stores will use every morning until Christmas Eve. Tom, Head of Data & Analytics, will not put it live on trust. He has two questions: is it right, and what will it cost?

This afternoon you answer them. You measure the assistant, find out why it is wrong, fix it, prove the fix and promote it. Then you estimate what it will cost each month and per store manager, and set a budget for the project and a daily limit for each person.

What are we evaluating?

The evaluation scores the whole assistant, then you fix what it finds in one of two places:

  • The agent: its instructions and orchestration, meaning how it picks a tool for each question and how it writes the answer. (Step 5)
  • The tools: what each tool gives back. The assistant has three: Cortex Analyst for the numbers, Cortex Search for the comments, and charts. This afternoon looks at one of them, the semantic view that Cortex Analyst writes its SQL from, with an evaluation of its own. (Step 4)

1

Freeze the current version

~5 min

Part 1: is it right? Tom Walsh: "The store managers like it. Before 72 stores lean on it every morning to Christmas Eve, I need to know it is right, and what it will cost." Before you change anything, freeze what the stores have now.

An agent keeps a working draft and a list of committed versions, and a committed version never changes. Freezing the assistant as it is now gives you a fixed point to measure against and to roll back to. Pinning it as the default keeps everyone on it while you change the draft: until you pin it, the default is the latest commit, so this afternoon's new version would reach every store manager before anyone had tested it. You never type a version number; the blocks look it up.

In lab3.sql, run this block. It checks that the production copy is in place, then commits the draft as a new version, labels it baseline and makes it the default.

sql
-- Lab 3 Step 1: check the production copy setup built, then freeze it as the baseline.
-- If anything is missing it stops and says what, and nothing is committed. Otherwise it commits the
-- draft as a new version, labels it baseline and makes it the default, so nothing you change later in
-- this lab reaches the store managers until you promote it.
-- The first three lines set this SQL file's context for the rest of the afternoon.
USE ROLE ACCOUNTADMIN;
USE WAREHOUSE WILDERNESS_WH;
USE SCHEMA WILDERNESS_HOL.LAB3_PRODUCTION;

EXECUTE IMMEDIATE $$
DECLARE
  v_tools   VARCHAR DEFAULT '';
  v_missing VARCHAR DEFAULT '';
  v_n       INT DEFAULT 0;
  v_version VARCHAR;
BEGIN
  BEGIN
    DESCRIBE AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT;
    SELECT ARRAY_TO_STRING(ARRAY_AGG(t.value:tool_spec:name::VARCHAR), ', ') INTO :v_tools
      FROM TABLE(RESULT_SCAN(LAST_QUERY_ID())) d, LATERAL FLATTEN(PARSE_JSON(d."agent_spec"):tools) t;
  EXCEPTION WHEN OTHER THEN v_tools := '';
  END;
  IF (NOT (CONTAINS(:v_tools, 'retail_analyst') AND CONTAINS(:v_tools, 'customer_feedback')
           AND CONTAINS(:v_tools, 'data_to_chart'))) THEN
    v_missing := v_missing || 'the production assistant and its three tools; ';
  END IF;

  SHOW CORTEX SEARCH SERVICES LIKE 'CSS_CUSTOMER_FEEDBACK' IN SCHEMA WILDERNESS_HOL.LAB3_PRODUCTION;
  SELECT COUNT(*) INTO :v_n FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()));
  IF (v_n <> 1) THEN v_missing := v_missing || 'the customer feedback search; '; END IF;

  SHOW SEMANTIC METRICS IN WILDERNESS_HOL.LAB3_PRODUCTION.SV_WILDERNESS_RETAIL;
  SELECT COUNT(*) INTO :v_n FROM TABLE(RESULT_SCAN(LAST_QUERY_ID())) WHERE "name" = 'RETURN_RATE';
  IF (v_n <> 1) THEN v_missing := v_missing || 'RETURN_RATE on the semantic view; '; END IF;

  SHOW DATASETS LIKE 'CHRISTMAS_EVAL_SET' IN SCHEMA WILDERNESS_HOL.LAB3_PRODUCTION;
  SELECT COUNT(*) INTO :v_n FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()));
  IF (v_n <> 1) THEN v_missing := v_missing || 'the evaluation dataset; '; END IF;

  IF (v_missing <> '') THEN
    RETURN 'MISSING: ' || RTRIM(:v_missing, '; ') || '. Nothing was frozen. See If you get stuck.';
  END IF;

  -- Run twice, it does not freeze again: the baseline stays the version you first measured.
  SHOW VERSIONS IN AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT;
  SELECT MAX("name") INTO :v_version FROM TABLE(RESULT_SCAN(LAST_QUERY_ID())) WHERE "alias" = 'BASELINE';
  IF (v_version IS NOT NULL) THEN
    RETURN 'Already frozen: the baseline is ' || :v_version || '. Nothing changed. Carry on with Step 2.';
  END IF;

  ALTER AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT
    COMMIT COMMENT = 'Baseline: the production copy, before any Lab 3 change';
  SHOW VERSIONS IN AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT;
  SELECT "name" INTO :v_version FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()))
    WHERE "name" IS NOT NULL ORDER BY "created_on" DESC LIMIT 1;
  EXECUTE IMMEDIATE 'ALTER AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT MODIFY VERSION '
                    || :v_version || ' SET ALIAS = baseline';
  EXECUTE IMMEDIATE 'ALTER AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT SET DEFAULT_VERSION = '''
                    || :v_version || '''';
  -- A commit leaves no draft; open a fresh one from the baseline for Step 5 to change.
  ALTER AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT ADD LIVE VERSION FROM LAST;
  RETURN 'All checks OK (assistant and tools, feedback search, RETURN_RATE, 8-question dataset). Baseline is '
         || :v_version || ', and it is the default.';
END;
$$;

SHOW VERSIONS IN AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT;

2

Run the evaluation

~15 min

Measure the frozen version on the questions store managers ask.

An agent evaluation asks the assistant a fixed set of questions and scores every answer. For each question you give what a right answer contains and the tools it should use. Three metrics, each scored 0 to 1 per question:

  • Answer correctness: a judge model compares the answer with the expected answer.
  • Logical consistency: a judge reads the agent's own steps and checks that they hang together, with no expected answer needed.
  • Tool selection accuracy: compares the tools it called with the tools you listed, worked out without a judge.

The run asks baseline, a version that cannot change, so whatever you edit while it runs does not change what is scored.

  1. Go to AI & ML » Agents and open WILDERNESS_ASSISTANT.
  2. Open the Evaluations tab and select Create evaluation run » Run an evaluation manually.
  3. Run name baseline_run. Agent version baseline.
  4. Dataset: select the existing dataset CHRISTMAS_EVAL_SET. Input query QUERY_TEXT.
  5. Metrics: Answer correctness, Logical consistency and Tool selection accuracy, each on version v3. Set the expected columns by hand, because the form can fill them in the wrong way round:
    • Answer correctness, expected answer: EXPECTED_TOOLS.
    • Tool selection accuracy, expected tool invocation: EXPECTED_TOOLS.
    • Logical consistency needs no expected column.
    QUERY_TEXT holds the questions. EXPECTED_TOOLS holds both the expected answer and the expected tool calls, so both metrics read it.
  6. Select Create.
  7. While it runs, run this in lab3.sql to see each question, what a right answer contains, and the tools it should use.

The scores say what is wrong. The records say why.

4

Fix issues in the semantic view

~12 min

Wilderness says launch weekend and Peak Week, and each means fixed dates. Nothing in the data says so, so the assistant guesses or asks.

Two features, used together:

  • A semantic view evaluation tests one layer, the SQL Cortex Analyst writes. The right answers are your own verified queries. During the run they are removed from a temporary copy of the view, so Cortex Analyst has to write the SQL itself, and its result is compared with yours.
  • Custom instructions tell Cortex Analyst what the tables cannot: here, which dates Wilderness's terms mean.

You add two verified queries, show that the view gets them wrong, add the definitions, and show that it now gets them right.

  1. Go to AI & ML » Cortex Analyst, open SV_WILDERNESS_RETAIL in LAB3_PRODUCTION (not the one in LAB1_ASSISTANT) and select Edit.
  2. Add each verified query below with its question and its SQL, then select Save. Each returns one total for a fixed range of days, so a wrong range gives a plainly wrong number.

Question: What were net sales over the launch weekend last year?

sql
SELECT MIN(s.order_date) AS first_day, MAX(s.order_date) AS last_day, SUM(s.net_sales) AS net_sales_aud
FROM __sales AS s
WHERE s.order_date BETWEEN '2025-11-01' AND '2025-11-03'

Question: What were net sales in Peak Week last year?

WHERE s.order_date BETWEEN '2025-12-18' AND '2025-12-24'

Both instructions are needed

At the build, SQL generation on its own still scored 0 of 2: Cortex Analyst kept asking what the terms meant before it reached the SQL. Question categorization lets the question through; SQL generation gets the dates right.

In a real project, change a copy first

A semantic view has no versions, so this edit reaches production the moment you save it, before the agent is evaluated again. Here you edit the production view to keep the afternoon short. In a real project, make the change on a development copy, evaluate it, then deploy it to the view production reads.

Why only these two queries

A question with one fixed total gives the same result every run. The morning's "stores running out of tents" query returns a list, and how a list is shaped can change its score from run to run, which would blur the before and after.

7

Promote the enhanced version

~4 min

The new version is better and nothing got worse. Put it in front of the stores.

Promoting is a label and a default, not a rebuild: the version that scored better is the version the store managers get, and the baseline stays one line away.

Run this block. It labels the candidate production, makes it the default and adds it to CoWork as Wilderness Assistant (production), in front of every store manager at once.

sql
-- Lab 3 Step 7: promote the candidate and put the production assistant in CoWork.
-- The candidate's label becomes production; the baseline stays as it is, so rolling back is one line.
-- @ACCOUNT_LEVEL
EXECUTE IMMEDIATE $$
DECLARE
  v_version VARCHAR;
  v_cowork  VARCHAR DEFAULT 'added to CoWork';
BEGIN
  SHOW VERSIONS IN AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT;
  SELECT "name" INTO :v_version FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()))
    WHERE UPPER("alias") = 'CANDIDATE';
  IF (v_version IS NULL) THEN
    RETURN 'No version is labelled candidate yet. Finish Step 6 first.';
  END IF;
  EXECUTE IMMEDIATE 'ALTER AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT MODIFY VERSION '
                 || :v_version || ' SET ALIAS = production';
  EXECUTE IMMEDIATE 'ALTER AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT SET DEFAULT_VERSION = '''
                 || :v_version || '''';
  BEGIN
    ALTER SNOWFLAKE INTELLIGENCE SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT ADD AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT;
  EXCEPTION
    WHEN OTHER THEN
      IF (CONTAINS(LOWER(:SQLERRM), 'already')) THEN
        v_cowork := 'already in CoWork';
      ELSE
        RAISE;
      END IF;
  END;
  RETURN 'Promoted ' || :v_version || ' to production; Wilderness Assistant (production) ' || :v_cowork;
END;
$$;

SHOW VERSIONS IN AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT;

-- Lab 3 Step 8: what this account has spent in the last 24 hours, by service.
-- Usage reaches this view an hour or two after it happens, so the last hour may be missing.
SELECT CASE SERVICE_TYPE
         WHEN 'CORTEX_AGENTS'            THEN 'Cortex Agents (the assistant outside CoWork, and evaluations)'
         WHEN 'SNOWFLAKE_COWORK'         THEN 'CoWork (the store managers'' questions)'
         WHEN 'SNOWFLAKE_INTELLIGENCE'   THEN 'CoWork (the store managers'' questions)'
         WHEN 'AI_FUNCTIONS'             THEN 'AI functions (Lab 2 AI_CLASSIFY and AI_COMPLETE)'
         WHEN 'AI_INFERENCE'             THEN 'AI inference (evaluation judges and other model calls)'
         WHEN 'CORTEX_SEARCH'            THEN 'Cortex Search (customer feedback)'
         WHEN 'SNOWFLAKE_COCO_SNOWSIGHT' THEN 'Cortex Code in Snowsight (Lab 2 and Lab 3)'
         WHEN 'WAREHOUSE_METERING'       THEN 'Warehouse (queries, the app, the automation)'
         ELSE SERVICE_TYPE
       END AS WHAT,
       ROUND(SUM(CREDITS_USED), 2) AS CREDITS
FROM SNOWFLAKE.ACCOUNT_USAGE.METERING_HISTORY
WHERE START_TIME >= DATEADD('hour', -24, CURRENT_TIMESTAMP())
GROUP BY WHAT
HAVING CREDITS > 0
ORDER BY CREDITS DESC;

11

Set a per-user quota

~8 min

One store manager, or a script running as one, could use up a day's AI spend in minutes, long before the budget notices. Tom wants a daily limit for each person, set from the estimate for one store manager.

A per-user quota gives every user in scope the same AI limit and blocks a user who reaches it within minutes, until the next day. It counts the services you add to it: here CoWork and Cortex Agents, the two ways a store manager reaches the assistant, because CoWork questions are billed to CoWork, not to the agent. You try it on a demo store manager, never on yourself.

  1. Run this block. It creates a demo store manager, tags them, sets 2 credits a day, checks who is in scope, then turns blocking on.
sql
-- Lab 3 Step 11: a daily AI limit for store managers, tried on a demo user.
-- A new quota covers every user in the account. This block narrows it to users tagged as store managers,
-- and leaves you out by name, so it can never block you during the workshop.
USE ROLE ACCOUNTADMIN;

-- A store manager to apply the limit to. No password: nobody signs in as this user today.
CREATE USER IF NOT EXISTS STORE_MANAGER_DEMO
  COMMENT = 'Wilderness workshop: a demo store manager for the AI quota';

-- The team tag that decides who the limit applies to.
CREATE TAG IF NOT EXISTS WILDERNESS_HOL.LAB3_PRODUCTION.TEAM ALLOWED_VALUES 'store_managers';
ALTER USER STORE_MANAGER_DEMO SET TAG WILDERNESS_HOL.LAB3_PRODUCTION.TEAM = 'store_managers';

CREATE OR REPLACE SNOWFLAKE.CORE.QUOTA WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_STORE_QUOTA();

-- What it counts: CoWork and Cortex Agents, the two ways a store manager reaches the assistant.
CALL WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_STORE_QUOTA!ADD_SHARED_RESOURCE('SNOWFLAKE INTELLIGENCE');
CALL WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_STORE_QUOTA!ADD_SHARED_RESOURCE('CORTEX AGENT');

-- Who it covers: users tagged store_managers, plus the demo user by name, never you.
CALL WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_STORE_QUOTA!SET_USER_TAGS(
  [[(SELECT SYSTEM$REFERENCE('TAG', 'WILDERNESS_HOL.LAB3_PRODUCTION.TEAM', 'SESSION', 'APPLYBUDGET')), 'store_managers']],
  'UNION');
CALL WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_STORE_QUOTA!INCLUDE_USERS(['STORE_MANAGER_DEMO']);
EXECUTE IMMEDIATE $$
BEGIN
  EXECUTE IMMEDIATE 'CALL WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_STORE_QUOTA!EXCLUDE_USERS(''USER'', [''' ||
                    REPLACE(CURRENT_USER(), '''', '''''') || '''])';
  RETURN 'You are excluded from the store manager quota';
END;
$$;

-- The limit: 2 credits per store manager per day.
CALL WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_STORE_QUOTA!SET_PER_USER_LIMIT(2, 'DAILY');

-- Check before blocking: the demo user under included users, and you under excluded users.
CALL WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_STORE_QUOTA!GET_QUOTA_SCOPE();

-- Block at the limit, and email the user when it happens.
CALL WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_STORE_QUOTA!SET_BLOCK_ENFORCEMENT_ENABLED(TRUE, TRUE);

-- The settings in force: a daily limit of 2 credits, blocking on.
CALL WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_STORE_QUOTA!GET_CONFIG();

Why the quota leaves you out by name

A new quota covers every user in the account. You have used far more than 2 credits today, so a quota that included you would block your CoWork and agent requests for the rest of the day. The block narrows the quota to a store-manager tag, excludes you by name, and turns blocking on only after the scope check has shown who is in it.

Step 5: use known-good instructions

If Cortex Code did not finish, or changed more than the instructions, run this instead. It replaces only the response and orchestration instructions in the agent's draft with the ones the build tested and keeps everything else, including the tool descriptions. Then carry on with Step 6.

sql
-- Lab 3 Step 5, known-good instructions: your agent's draft as it is, with improved instructions only.
EXECUTE IMMEDIATE $$
DECLARE
  v_spec VARIANT;
  v_ins VARIANT;
BEGIN
  -- Open a draft from the latest version if there is none yet.
  BEGIN
    ALTER AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT ADD LIVE VERSION FROM LAST;
  EXCEPTION WHEN OTHER THEN NULL;
  END;
  SHOW VERSIONS IN AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT;
  SELECT PARSE_JSON("agent_spec") INTO :v_spec FROM TABLE(RESULT_SCAN(LAST_QUERY_ID())) WHERE "name" IS NULL;
  v_ins := COALESCE(v_spec:instructions, OBJECT_CONSTRUCT());
  v_ins := OBJECT_INSERT(v_ins, 'response',
    'You help Wilderness Outfitters store managers and merchandisers through Christmas trading. Use plain Australian English and short sentences. Give the answer first, then the numbers behind it, and say which dates you used. Show money as AUD, for example AUD 1,234, never a bare $ sign. Quote customers word for word and name the source. Do not use emoji or marketing language. If a question is outside Wilderness sales, stock, returns and customer feedback, say so in one sentence and offer what you can answer instead. Do not send people to other websites or apps.', TRUE);
  v_ins := OBJECT_INSERT(v_ins, 'orchestration',
    'Use retail_analyst for any number and customer_feedback for what customers said. Call each tool once per question, and call it again only if the first result was empty or failed. For ''why'' and ''what can we do'' questions use both tools, retail_analyst first. Wilderness trading terms such as the launch weekend, Peak Week and the Christmas trading period are defined in the semantic view: pass the user''s words to retail_analyst rather than guessing dates or asking the user what they mean. Chart comparisons and trends.', TRUE);
  v_spec := OBJECT_INSERT(v_spec, 'instructions', v_ins, TRUE);
  EXECUTE IMMEDIATE 'ALTER AGENT WILDERNESS_HOL.LAB3_PRODUCTION.WILDERNESS_ASSISTANT MODIFY LIVE VERSION SET SPECIFICATION = '''

END;
$$;
