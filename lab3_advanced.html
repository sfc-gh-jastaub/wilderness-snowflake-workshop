The eight questions

Run this in lab3.sql to see each question, what a right answer contains, and the tools it should use.

sql
-- Lab 3 Step 2, block 1: the eight questions and what a right answer contains.
SELECT QUESTION_ID AS "#",
       INPUT_QUERY AS QUESTION,
       GROUND_TRUTH:ground_truth_output::VARCHAR AS RIGHT_ANSWER,
       ARRAY_TO_STRING(TRANSFORM(GROUND_TRUTH:ground_truth_invocations::ARRAY, t -> t:tool_name::VARCHAR), ', ') AS EXPECTED_TOOLS
FROM WILDERNESS_HOL.LAB3_PRODUCTION.AGENT_EVAL_QUESTIONS
ORDER BY QUESTION_ID;
#What it tests
1 to 3The morning's questions: tents, sleeping gear, and why the Summit 2P comes back. Question 3 needs both tools.
4Customer comments only, so the assistant should use the search and nothing else.
5 and 7Wilderness's launch weekend, a trading term with its own dates: 1 to 3 November.
6The financial year. A control: it should pass today.
8The weather. The assistant has no weather data, so the right answer says so and stops there.
What each metric scores

Answer correctness: a judge model compares the answer with the expected answer. Logical consistency: a judge reads the agent's own steps and checks that they hang together, with no expected answer needed. Tool selection accuracy compares the tools it called with the tools you listed, and is worked out without a judge. Each is scored 0 to 1 per question.

Why a version, and why scores move

The run asks baseline, a version that cannot change, so whatever you edit while it runs does not change what is scored. Each run asks the questions again, and models do not answer the same way twice, so a score can move by a few points between two runs of the same version. Read the pattern, not the second decimal place.

Wait until baseline_run shows Completed before Step 3.

4

Fix Wilderness's definitions in the semantic view

~14 min

Wilderness says launch weekend and Peak Week, and each means fixed dates. Nothing in the data says so, so the assistant guesses or asks. The fix goes in the semantic view, where every agent and tool that reads it will get it. You prove it with a semantic view evaluation, before and after.

What a semantic view evaluation is

It tests one layer: the SQL Cortex Analyst writes. The right answers are your own verified queries. During the run they are removed from a temporary copy of the view, so Cortex Analyst has to write the SQL itself, and its result is compared with yours.

1. Add two verified queries

  1. Go to AI & ML » Cortex Analyst, open SV_WILDERNESS_RETAIL in LAB3_PRODUCTION (not the one in LAB1_ASSISTANT) and select Edit.
  2. Add each verified query below with its question and its SQL, then select Save.

Question: What were net sales over the launch weekend last year?

sql
SELECT MIN(s.order_date) AS first_day, MAX(s.order_date) AS last_day, SUM(s.net_sales) AS net_sales_aud
FROM __sales AS s
WHERE s.order_date BETWEEN '2025-11-01' AND '2025-11-03'

Question: What were net sales in Peak Week last year?

sql
SELECT MIN(s.order_date) AS first_day, MAX(s.order_date) AS last_day, SUM(s.net_sales) AS net_sales_aud
FROM __sales AS s
WHERE s.order_date BETWEEN '2025-12-18' AND '2025-12-24'

Each returns one total for a fixed range of days, so a wrong range gives a plainly wrong number.

2. Evaluate before the fix

  1. Open the semantic view's Evaluations tab and select Create evaluation run.
  2. Run name before_fix, metric SQL correctness on v3.
  3. Select only the two queries you just added, then Run evaluation.
You should see

After 2 to 3 minutes, 0 of 2 correct. Open a result: Cortex Analyst did not answer, and asked what "Peak Week" or "launch weekend" means.

Why only these two

A question with a fixed total gives the same result every run. Lab 1's sleeping-gear query returns a list, and how the list is shaped can change its score from run to run, which would blur the before and after.

3. Add the definitions

Custom instructions tell Cortex Analyst things the tables cannot. In the editor, open Custom instructions, paste the two blocks below into their fields, and select Save.

Question categorization, so a question that uses a Wilderness term counts as clear instead of unclear:

text
Wilderness uses its own trading terms, and questions that use them are clear. The launch weekend is 1 to 3 November. Peak Week is 18 to 24 December. The Christmas trading period is 1 November to 24 December. 'Last year' means 2025.

SQL generation, so the SQL uses the right dates:

text
Wilderness uses these trading terms. The launch weekend is the first three days of Christmas trading, 1 to 3 November. Peak Week is the seven days to Christmas Eve, 18 to 24 December. The Christmas trading period runs from 1 November to 24 December, never calendar December. 'Last year' and 'last Christmas' mean 2025. The financial year runs from 1 July to 30 June, and 'last financial year' means FY26, 1 July 2025 to 30 June 2026. Always say which dates you used.
Both are needed

At the build, SQL generation on its own still scored 0 of 2: Cortex Analyst kept asking what the terms meant before it reached the SQL. Question categorization lets the question through; SQL generation gets the dates right.

4. Evaluate after the fix

Create a second run, after_fix, the same way, on the same two queries.

You should see

2 of 2 correct, with SQL that uses 1 to 3 November 2025 and 18 to 24 December 2025.

5. Look at Improve

Open after_fix and select Improve in the accuracy panel. It suggests changes to the semantic view from the results. Read one; you do not need to accept it.

Run it whenever the view changes

A semantic view evaluation takes minutes and tests only the view. Run it every time someone changes the view, so a broken definition is caught before any agent uses it.

1. What today has cost

sql
-- Lab 3 Step 7, block 1: what this account has spent in the last 24 hours, by service.
-- Usage reaches this view an hour or two after it happens, so the last hour may be missing.
SELECT CASE SERVICE_TYPE
         WHEN 'CORTEX_AGENTS'            THEN 'Cortex Agents (the assistant outside CoWork, and evaluations)'
         WHEN 'SNOWFLAKE_COWORK'         THEN 'CoWork (the store managers'' questions)'
         WHEN 'SNOWFLAKE_INTELLIGENCE'   THEN 'CoWork (the store managers'' questions)'
         WHEN 'AI_FUNCTIONS'             THEN 'AI functions (Lab 2 AI_CLASSIFY and AI_COMPLETE)'
         WHEN 'AI_INFERENCE'             THEN 'AI inference (evaluation judges and other model calls)'
         WHEN 'CORTEX_SEARCH'            THEN 'Cortex Search (customer feedback)'
         WHEN 'SNOWFLAKE_COCO_SNOWSIGHT' THEN 'Cortex Code in Snowsight (Lab 2 and Lab 3)'
         WHEN 'WAREHOUSE_METERING'       THEN 'Warehouse (queries, the app, the automation)'
         ELSE SERVICE_TYPE
       END AS WHAT,
       ROUND(SUM(CREDITS_USED), 2) AS CREDITS
FROM SNOWFLAKE.ACCOUNT_USAGE.METERING_HISTORY
WHERE START_TIME >= DATEADD('hour', -24, CURRENT_TIMESTAMP())
GROUP BY WHAT
HAVING CREDITS > 0
ORDER BY CREDITS DESC;

Why the secondary-roles line matters

New users get all their roles as secondary roles. Without USE SECONDARY ROLES NONE, ACCOUNTADMIN stays active behind the store-manager role, and the denial test passes for the wrong reason. Test access with secondary roles off.

Three rules for tuning

Change one thing at a time, so you know what moved the score. Look for questions that got worse, not only the average. And do not tune to the eight questions: when a fix only makes sense for one question, add more questions to the dataset instead.
