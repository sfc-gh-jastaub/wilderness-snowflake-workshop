1

Open a Workspace and brief Cortex Code

~5 min

Cortex Code is an agent in Snowsight that writes and runs SQL and Python for you, in your account, with your rights. You tell it what you want; it does the work and shows you the result. The first prompt sets the rules for the whole session.

  1. Go to Projects » Workspaces and open the workspace with your SQL file from Lab 1.
  2. Open the Cortex Code panel.
  3. Paste prompt 0 and send it.
  4. The first time Cortex Code asks to run a command, choose Always allow. It then runs each statement without asking again.

Prompt 0:

cortex code
I'm working in Snowflake database WILDERNESS_HOL, warehouse WILDERNESS_WH, for Wilderness Outfitters, an Australian outdoor retailer. For this whole session: execute every statement rather than drafting it, use fully qualified three-part names, and after you create any object run a query that proves it exists and show me the result.
You should see

Cortex Code confirms the database and warehouse, and may run a quick query to check it can see WILDERNESS_HOL.

Why the brief is so short

You do not tell Cortex Code which tables exist, how they join or what dates the data covers. It reads the account and works that out. Prompt 0 only sets the rules for the session.

2

Get to know the data and find the problem

~12 min

Start the way an analyst would on a new engagement: what does the data say about Wilderness, and does Martha's brief hold up? These three prompts give the same picture the Wilderness Assistant gave this morning, worked out from the raw tables.

Prompt 1:

cortex code
Give me a business overview of what is in WILDERNESS_HOL.RAW, written for a merchandising manager: what each table tells us about Wilderness's stores, products, customers, sales, returns, stock and customer feedback, what period the sales cover, and how it all connects. Keep it to one short table.
You should see

One table in plain business terms: stores in every state plus online, products with the Christmas catalogue flagged, Basecamp loyalty members, sales from July 2024 to 3 November 2026, returns linked to the sale they came from, stock by store and batch at 3 November, and customer comments. Cortex Code found the dates and the links itself.

Wilderness holds about 40% more tents than it sold last Christmas, in every state. That is only a problem if customers are not buying them where they are, so the next prompt checks where tent sales are growing this year.

Prompt 2:

cortex code
Compare tent units sold from 1 to 3 November 2026 with 1 to 3 November 2025, by state. Run it and chart it.
You should see

Tent sales up about 45% in New South Wales and Queensland, and only about 10% in Victoria, Tasmania and South Australia. The stock went everywhere; the extra demand did not.

Then the rest of the basket. A family that buys a tent also needs somewhere to sleep, something to cook on and a light, and Wilderness ordered that kit at last year's levels. Where tents sell faster, the kit runs out first.

Prompt 3:

cortex code
Last Christmas, which at Wilderness ran from 1 November to 24 December 2025, what share of orders that contained a tent also contained an item with KIT_GROUP SLEEP, COOK or LIGHT? Then find the ten stores that are shortest of sleeping gear for the tents they still have to sell before Christmas Eve. Check whether WILDERNESS_HOL.ANALYTICS already has a view for this before you build anything. Run both.
You should see

About 61% of tent orders also had sleeping gear, 34% cooking gear and 28% a light. Cortex Code finds the view V_KIT_COVER and lists ten stores, mostly in New South Wales and Queensland, that run out of sleeping gear in early December.

What V_KIT_COVER is, and why it already exists

For each store it works out how many sleeping bags, mats, stoves and lights the tents still to sell will need, using last Christmas's basket mix, and compares that with the stock held. Setup built it because the Wilderness Assistant answered the sleeping-gear question from it in Lab 1. Reusing it here means the plan and the assistant give the same numbers.

3

Build the stock plan in a notebook, with an AI function

~20 min

You now know the shape of the problem: too many tents in the south, too few in the north, and not enough kit to go with them. What nobody can tell Martha yet is what to do about it in each store: which tents go back to the supplier, which move to a store that will run out, and what to reorder in time for Christmas.

That answer needs three things the data does not hold today:

  • A forecast for every store to Christmas Eve, so you can see who runs out and who is left holding stock.
  • Which returns are real faults. The supplier takes back unsold stock only from a batch with too many faults, and the returns desk codes most of them simply as "faulty".
  • A rule that turns each store's numbers into one action: send back, transfer out, transfer in, reorder or mark down.

The four prompts build these in a notebook the team can rerun and check, then publish the result as a view.

Prompt 4: stock and forecast

cortex code
Create a notebook called christmas_stock_plan in this Workspace. In the first cells, load inventory at 3 November 2026 for Christmas catalogue products by store and batch, and forecast units to sell from 4 November to 24 December as last year's average weekly Christmas units times 51/7 times the state and category sales index since 1 November. Run every cell.
You should see

A new notebook with its cells run. Most products have one batch; the Summit 2P has two, B26-02 and B26-07.

Prompt 5: sort the return comments with an AI function

Stores give every return a coarse reason code. The comment says more: a snapped pole is a fault, a customer who could not pitch the tent is not. Wilderness's supplier contract pays out only on faults.

cortex code
Add a cell that uses AI_CLASSIFY to label every comment in WILDERNESS_HOL.RAW.CUSTOMER_FEEDBACK with FEEDBACK_SOURCE 'RETURN_COMMENT' for product SKU-TNT-0102 since 1 July 2026 as one of POLE_OR_FRAME_FAULT, SEAM_OR_WATERPROOFING_FAULT, COULD_NOT_PITCH, CHANGE_OF_MIND or OTHER. Save the result as WILDERNESS_HOL.ANALYTICS.TENT_RETURN_REASONS with columns FEEDBACK_ID, PRODUCT_ID, BATCH_CODE, FEEDBACK_DATE, REASON. Run it, then show the count by BATCH_CODE and REASON.
You should see

About 500 comments classified in a minute or two. Most B26-07 comments are pole or seam faults, and a block of about one in seven are COULD_NOT_PITCH: first-time campers, not faults.

An AI function is SQL

The model runs where the data is, on every row, and the result is a table you can join like any other.

Prompt 6: what is at risk

cortex code
Add a cell that calculates an estimated defect return rate per batch as the batch return rate times the share of its comments that are faults, then classifies each store and product as STOCKOUT (less than 6.5 weeks of forecast cover), OVERSTOCK (more than 7.5 weeks of cover) or OK, calculates stock at risk in AUD at cost, and charts it by state. Run it.
You should see

An estimated defect rate of about 12% for B26-07, above the 8% the contract allows, and about 1% for B26-02. The chart puts most of the stock at risk in Victoria.

Prompt 7: publish the plan as a view

cortex code
Add a final cell that creates the view WILDERNESS_HOL.ANALYTICS.V_CHRISTMAS_STOCK_RISK, one row per store and Christmas catalogue product, with columns STORE_ID, STORE_NAME, STATE, LATITUDE, LONGITUDE, PRODUCT_ID, PRODUCT_NAME, KIT_GROUP, UNIT_COST, ON_HAND_UNITS, ON_ORDER_UNITS, RETURNABLE_UNITS (on-hand units in batches whose estimated defect rate is above 8%), FORECAST_UNITS_TO_XMAS, WEEKS_OF_COVER, EST_DEFECT_RETURN_RATE, RISK, EXCESS_UNITS, SHORTFALL_UNITS, STOCK_AT_RISK_AUD (excess units times UNIT_COST) and SUGGESTED_ACTION. SUGGESTED_ACTION has one value per row: for OVERSTOCK, RETURN TO SUPPLIER if RETURNABLE_UNITS is above 0, else TRANSFER OUT if another store has a STOCKOUT row for the same product, else MARK DOWN BOXING DAY; for STOCKOUT, TRANSFER IN if any store has an OVERSTOCK row for the product, else REORDER BY 13 NOV; otherwise NONE. Run it, then SELECT the top 10 rows by STOCK_AT_RISK_AUD.
You should see

Summit 2P rows in Victorian and Tasmanian stores at the top, with Ringwood first, marked RETURN TO SUPPLIER against the B26-07 units.

4

Complete the kit: an offer for Basecamp members

~10 min

The stock plan protects margin. This step finds sales.

Six in ten tent orders last Christmas also had sleeping gear. Some of this week's tent buyers left without it, and the ones who are Basecamp members can be sent an offer. There is a catch: an offer from a store that is already short of sleeping gear brings customers in for stock that is not there, and makes the shortage worse. So the offer goes only where the store can sell the kit.

Prompt 8:

cortex code
Find the Basecamp members who bought a tent from 1 to 3 November 2026 but no item with KIT_GROUP SLEEP in the same order. For online orders use the member's home store. Flag whether that store is short of sleeping gear in WILDERNESS_HOL.ANALYTICS.V_KIT_COVER, and send an offer only where it is not. Save one row per member as WILDERNESS_HOL.ANALYTICS.KIT_OFFER_AUDIENCE with columns MEMBER_ID, FIRST_NAME, TIER, TENT_NAME, STORE_ID, STORE_NAME, STATE, STORE_SHORT_OF_SLEEP, SEND_OFFER. Then show how many members get an offer, how many are held back, and the sales opportunity in AUD if each one spends on sleeping gear what last Christmas's tent orders with sleeping gear spent on it.
You should see

About 750 members who bought a tent without sleeping gear. About 400 get an offer and about 350 are held back, most of them in New South Wales and Queensland where the kit is short. At about AUD 113 of sleeping gear per tent order, the offer is worth about AUD 46,000, from three days of sales.

Prompt 9:

cortex code
Add a cell that uses AI_COMPLETE with the model claude-sonnet-4-6 to write the offer email for one member in KIT_OFFER_AUDIENCE who gets an offer. Thank them by name for the tent they bought at their store, and offer 15% off a sleeping bag or mat in store before 24 December. Plain Australian English, under 80 words, no exclamation marks. Run it and show me the email.
You should see

One email in a few seconds, with the member's name, their tent and their store, for example "Thanks for picking up the Summit 2P Tent at Wilderness Ringwood this week". The wording changes from run to run. In Step 5 the app writes this email for any member you pick.

Why one

AI_COMPLETE runs once per row and is charged by the amount of text. Check the wording on one member before anyone writes four hundred.

Why the assistant could not do this

Member names are not in the semantic view, by design: store managers ask about stock and sales, not about individual customers. An analyst with the right role can work with them. In Lab 3 you control who sees what.

Stuck? Use the finished notebook

Section 6 of the finished notebook, notebooks/lab2_christmas_stock_plan.ipynb, creates KIT_OFFER_AUDIENCE with the same columns and writes one email. If you opened it in Step 3, run the cells under 6. Complete the kit.

5

Ship it as an app

~10 min

Marketing will not open a notebook, and neither will the merchandisers. Give them one app that tells the story from the top: every tent sold this week, narrowed down to the members worth an offer, then one member's email written while they watch. The stock plan sits on a second tab.

Prompt 10:

cortex code
Create a Streamlit in Snowflake app called WILDERNESS_HOL.APPS.CHRISTMAS_STOCK_PLANNER on the warehouse runtime, with two tabs. The first tab, Kit offer, shows a funnel as four KPI tiles: tent orders from 1 to 3 November 2026 in WILDERNESS_HOL.RAW.FCT_SALES_LINE, the Basecamp members who placed them, the members in WILDERNESS_HOL.ANALYTICS.KIT_OFFER_AUDIENCE, and the members with SEND_OFFER true. Under the tiles, a bar chart of offers and held-back members by state, then the table of members who get an offer with a state filter. The second tab, Stock plan, reads WILDERNESS_HOL.ANALYTICS.V_CHRISTMAS_STOCK_RISK and shows KPI tiles for stock at risk, units returnable to suppliers and number of stockout stores, a bar chart of stock at risk by state, and a table of suggested actions. Use three-part names. Deploy it, run it and give me the link.
You should see

A link to the app. The Kit offer tab narrows about 2,800 tent orders to about 2,000 Basecamp members, about 750 without sleeping gear and about 400 whose store has the kit. The chart shows New South Wales and Queensland holding back the most members. The Stock plan tab shows about AUD 900,000 of stock at risk and about 40 stores that will run out of something.

Prompt 11:

cortex code
On the Kit offer tab, under the member table, let me pick one member and add a Write the email button. When I press it, call AI_COMPLETE with claude-sonnet-4-6 to write that member's offer email with the same prompt as the notebook, and show the email on screen. Do not send it anywhere. Redeploy the app and run it.
You should see

Pick a member, press Write the email, and a few seconds later their email appears: their name, their tent, their store and the 15% offer. Pick another member and the next email is written for them.
