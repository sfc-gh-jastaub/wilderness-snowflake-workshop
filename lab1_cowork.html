Overview

The situation

Last Christmas, Wilderness ran out of tents early in the season. So this year it bought 40% more tents for every store in every state. Three days into Christmas trading, the buying has changed: demand is much stronger in some states than others. Wilderness has to decide where to send more stock and what stock to move between stores. First, the 72 store managers need to know where they stand. This lab gives them an assistant that tells them.

What you will use

Cortex Code Cortex Search Semantic views Cortex Analyst Cortex Agents Snowflake CoWork Artifacts Automations Agent skills

What you will build

  • Run one script that loads Wilderness's data into your account.
  • Ask Cortex Code what the data holds, in business terms.
  • Make 20,000 customer comments searchable with Cortex Search.
  • Find out what the semantic view knows, then teach it Wilderness's words.
  • Create the Wilderness Assistant with four tools (the numbers, the customer comments, charts and code) and put it in CoWork.
  • Ask it where you stand, from the numbers, from what customers say and from both, then save the answer and have it emailed every morning.

1

Run the setup script

~6 min

Everything in this lab runs on Wilderness's own data: its stores, products, Basecamp members, sales since July 2024, returns, stock and customer comments. First, load it into your account.

One script does it. It connects your account to the workshop's GitHub repository and runs the rest of the setup from there, on one small warehouse that suspends after a minute. It takes about two minutes, and it also builds the starter semantic view you meet in Step 4.

  1. In Snowsight, go to Projects » Workspaces.
  2. Select + Add new » SQL File.
  3. Copy the block below, paste it into the file and select Run all.
sql
-- =====================================================================================
-- 00_bootstrap.sql  ·  Wilderness Outfitters workshop
-- The only thing you paste. It connects your account to the workshop's GitHub repo and
-- runs the rest of the setup from there.
-- =====================================================================================
USE ROLE ACCOUNTADMIN;
CREATE WAREHOUSE IF NOT EXISTS WILDERNESS_WH WAREHOUSE_SIZE = SMALL AUTO_SUSPEND = 60 AUTO_RESUME = TRUE
  INITIALLY_SUSPENDED = TRUE;
USE WAREHOUSE WILDERNESS_WH;
CREATE DATABASE IF NOT EXISTS WILDERNESS_HOL;
CREATE SCHEMA IF NOT EXISTS WILDERNESS_HOL.SETUP;

CREATE OR REPLACE API INTEGRATION WILDERNESS_GIT_API
  API_PROVIDER = git_https_api
  API_ALLOWED_PREFIXES = ('https://github.com/sfc-gh-jastaub/')
  ENABLED = TRUE;

CREATE OR REPLACE GIT REPOSITORY WILDERNESS_HOL.SETUP.WORKSHOP_REPO
  API_INTEGRATION = WILDERNESS_GIT_API
  ORIGIN = 'https://github.com/sfc-gh-jastaub/wilderness-snowflake-workshop.git';

-- Core setup, about 2 minutes: infrastructure, data, feedback, semantic view, Lab 3 assets
EXECUTE IMMEDIATE FROM @WILDERNESS_HOL.SETUP.WORKSHOP_REPO/branches/main/setup/10_setup_core.sql;

SELECT STEP, STATUS, ROWS_AFFECTED, LOGGED_AT FROM WILDERNESS_HOL.SETUP.SETUP_LOG ORDER BY LOGGED_AT;
You should see

The setup log, with every step OK.

If a step shows something other than OK

EMAIL shows NO_EMAIL_ON_USER when your Snowflake user has no email address. Add one under your name » Settings, then select Run all again. Running the script twice is safe: it replaces what it built and leaves the same data.

2

Ask what is in the data

~4 min

Before you build anything for the store managers, get to know the data the way they would: what is in it, in business terms, and what period it covers.

Cortex Code is an agent in Snowsight that writes and runs SQL for you, in your account, with your rights. You say what you want; it works out how, runs it and shows you the result. Every build step in this lab is one prompt to it.

  1. In the same Workspace, open the Cortex Code panel.
  2. Paste the prompt below.
  3. Before you send it, change the approvals setting at the bottom of the panel from Default approvals to Bypass approvals, so Cortex Code runs each statement without stopping to ask.

Prompt 0:

cortex code
Use database WILDERNESS_HOL and warehouse WILDERNESS_WH. The data is in schema RAW. Build everything in schema LAB1_ASSISTANT. Run every statement, don't just draft it.
Give me a business overview of what is in WILDERNESS_HOL.RAW, written for a store manager.
You should see

A short overview in plain terms: 72 stores across the states and territories, 1,200 products with the Christmas catalogue flagged, about 180,000 Basecamp loyalty members, 2.8 million sales lines from July 2024 to 3 November 2026, returns linked to the sale they came from, stock by store at 3 November, and 20,000 customer comments.

You did not describe the data

You did not tell Cortex Code which tables exist, how they join or what dates they cover. It read the account and worked that out.

3

Make the customer comments searchable

~5 min

What customers say is often the first sign of trouble. Wilderness has 20,000 customer comments in one table: product reviews, notes from the returns desk and messages to the contact centre. Nobody has time to read them all, and a keyword search misses most of what matters: one customer writes "the pole snapped at the hub", another "the frame broke".

Cortex Search finds comments by what they mean, not the exact words, so both of those come back for the same question. You point it at a column of text, and Snowflake builds the search index and keeps it up to date.

Ask Cortex Code to set it up, then test it with a question.

Prompt 1:

cortex code
Create a Cortex Search service CSS_CUSTOMER_FEEDBACK on FEEDBACK_TEXT in RAW.CUSTOMER_FEEDBACK, with product, batch, store, state, rating and source as filters, refreshed daily. Then find the top three comments about tents coming back broken.
You should see

The statement Cortex Code wrote and ran, then three comments quoted word for word. All three are about the Summit Tent, the tent on the Christmas catalogue cover: a pole snapping at the hub, or seams leaking in the rain. The index takes about a minute to build.

4

Ask what the semantic view knows

~3 min

The comments say what customers think. Where Wilderness stands, with tents sold, returned, on the shelf and needed by Christmas Eve, is in the numbers. For an assistant to answer from them, it needs a map of those tables in Wilderness's terms.

That map is a semantic view. It describes the tables of sales, returns and stock in business terms: what a sale is, how a return links to a sale, what "return rate" means. An agent reads it to turn a question into the right query. Setup created a starter one, SV_WILDERNESS_RETAIL.

Before you change it, find out what it already knows.

Prompt 2:

cortex code
What does the semantic view LAB1_ASSISTANT.SV_WILDERNESS_RETAIL cover today? List its tables, metrics and verified queries in plain terms, and what a store manager could not ask it yet.
You should see

A plain list. It covers sales, returns, stock, and tent cover by store, with the tents each store will have left over or be short of by Christmas Eve. It has no return rate, no synonyms for the words store managers use, and no verified queries.

5

Teach the semantic view Wilderness's words

~8 min

Store managers ask about "tents", "returns" and "left over", and they want a return rate. The view does not know those words yet, so questions phrased that way would miss.

You teach a semantic view in three ways:

  • A metric: a calculation it can reuse, such as a return rate.
  • Synonyms: the words people actually use.
  • Verified queries: questions with SQL you have checked. When someone asks something similar, Cortex Analyst starts from the checked SQL.

Prompt 3:

cortex code
Improve SV_WILDERNESS_RETAIL: add a RETURN_RATE metric (units returned / units sold), synonyms for tent, Christmas range, returns and left over, and two verified queries written against the semantic view's own tables, not RAW: the return rate by batch, and the stores running out of tents. Then give me a short summary of what you changed.
You should see

Cortex Code applies the changes in one go, then sums them up: the RETURN_RATE metric, the synonyms and the two verified queries. Its wording will differ from your neighbour's.

6

Create the agent and put it in CoWork

~8 min

You now have the comments and the numbers ready to be asked. The store managers need one place to ask both, and they will not open Snowsight. They use CoWork, the chat app at ai.snowflake.com.

An agent answers a question by choosing tools and putting the results together. This one gets four:

  • Cortex Analyst, for numbers, through the semantic view.
  • Cortex Search, for what customers said.
  • Data to Chart, which turns a result into a chart.
  • Code execution, which writes and runs Python. In Step 8 it builds an HTML page from your answers.

Its instructions tell it who it is talking to and how to answer. CoWork lists only the agents an administrator adds to it, so the same prompt adds this one.

Prompt 4:

cortex code
Create agent WILDERNESS_ASSISTANT, display name Wilderness Assistant, for 72 store managers, with four tools: retail_analyst (Cortex Analyst on SV_WILDERNESS_RETAIL), customer_feedback (Cortex Search on CSS_CUSTOMER_FEEDBACK), data_to_chart and code_execution. Warehouse WILDERNESS_WH. Instructions: plain Australian English, answer first, AUD, and say when the data cannot answer. Add four sample questions: one that needs only the customer comments, one that needs only the numbers, one simple one that needs both, and one harder one that needs both and asks for a chart worth keeping. Then add it to CoWork and show me it is listed.
You should see

The agent created with four tools, retail_analyst, customer_feedback, data_to_chart and code_execution, the instructions and four sample questions Cortex Code wrote for it, and a list that includes WILDERNESS_ASSISTANT in CoWork.

"The store managers can't use it yet"

Cortex Code may add that store managers need a role with access to the agent and its tools. That is right, and you do not need it today: you sign in as ACCOUNTADMIN, so the agent is yours to use in CoWork straight away. A store-manager role with only the access it needs is the next step before go-live.

7

Use it in CoWork

~8 min

Now use it the way a store manager will: start wide with the questions anyone would ask, then zoom in on the tent customers are bringing back.

CoWork shows the agent's sample questions, so a store manager does not have to start from a blank box. For each question the agent picks its tools: the numbers, the comments, or both in one answer. The thinking steps show which it used. A question that needs both, counting the returns, quoting the customers and charting the result, is the one no report or chatbot answers on its own.

  1. Open ai.snowflake.com in a new tab and sign in with the same account, or in Snowsight go to Snowflake » AI » CoWork.
  2. Choose Wilderness Assistant.
  3. Select the four sample questions Cortex Code wrote for it, one at a time, in one conversation, ending with the harder one.

If the sample questions are missing or do not work, ask these instead, in this order.

Simple: the comments only.

cowork
What are customers saying about our tents?

Simple: the numbers only.

cowork
Where will we run out of tents before Christmas, and where will we have tents left over?

Simple: both.

cowork
What is the Summit Tent's return rate, and what do customers say when they bring one back?

Harder: both, with a chart.

cowork
Customers are bringing the Summit Tent back. What are they saying, and is one batch worse? Show the return rate by batch in a chart that makes the worst batch stand out.
You should see

Each answer names its tools in the thinking steps:

  • Comments only (customer_feedback): most tent comments are happy, but one tent stands out, the Summit Tent, with poles snapping and seams leaking.
  • Numbers only (retail_analyst): every store in New South Wales and Queensland, 33 in all, runs out around 18 December, about 3,000 tents short; every other store, 39 in all, has tents left over, about 5,200 on Boxing Day.
  • Both, simple: the Summit Tent's return rate with customers quoted on why.
  • Both, harder: comments quoted word for word about poles snapping at the hub and seams leaking, batch B26-07 coming back at about 18% against about 4% for every other batch, and a chart of the return rate by batch with B26-07 standing out.
Keep this conversation open

You save the chart from the harder question in Step 8.

8

Keep the answer: artifacts

~6 min

The return-rate chart from the harder question is worth keeping. Tomorrow, with a new day of returns, someone will want it again, and a chat answer disappears into the history.

An artifact keeps it: a saved chart that reruns its query when you open it.

  1. On the return-rate chart from Step 7, select Explore. If none of your answers had a chart, ask the harder question from the list in Step 7.
  2. Select Save as favourite.
  3. Go to the Artifacts hub and open the chart.
You should see

The chart in the Artifacts hub, marked as a favourite, with the date it last ran.

It reruns its query

The chart reruns its SQL when you refresh it, with your own access rights. A question like "last 30 days" moves forward each time; fixed dates stay fixed. A shared conversation is different: it is a snapshot and never reruns.

CoWork can also turn the conversation into a file: a PDF, Word, PowerPoint or HTML page. It writes the file with the agent's code execution tool, the fourth tool you gave it in Step 6.

Go back to the Step 7 conversation and ask:

cowork
Generate an interesting HTML diagram for this.
You should see

A code step in the thinking steps, then an HTML page shown in the chat, built from the conversation: batch B26-07 coming back at about 18% against about 4% for the other batches, with what customers said about the poles and seams. If CoWork asks before it runs code, allow it. The design is CoWork's choice, so yours will differ from your neighbour's.

A snapshot, not a rerun

Unlike the saved chart, the HTML page does not rerun anything. It shows the numbers as they were when CoWork made it. HTML generation in CoWork is in preview.

9

Schedule it: automations

~5 min

Stores have to act before the 13 November reorder deadline. Every morning the store managers need the stores running out of tents in their inbox, without anyone remembering to ask.

An automation asks a question again on a schedule and emails you the answer.

  1. Open the Automations tab and select Create in chat.
  2. Paste the prompt below and send it.
  3. Confirm the schedule CoWork proposes. The automation appears in the Automations tab with its next run time.
  4. Open the automation and select Run now, so you do not have to wait for the hour.
cowork
Send me the stores running out of tents every hour.
You should see

One automation marked Active with a next run time within the hour. A few minutes after Run now, an email arrives listing the 33 stores in New South Wales and Queensland that run out of tents. It also appears in the automation's run history.

It runs every hour until you change it

Each run asks the question again as you, against the latest data, on your warehouse. Hourly is for today, so you see it work. In Lab 3 you count what it costs and move it to weekdays at 7am, the schedule a store manager would use. Cleanup deletes it.

10

Brief Martha: a skill that emails a report Optional

~10 min

Martha wants a briefing every morning, and she wants it in the same shape each day. The automation's summary is worded however the assistant likes that day.

A skill is a folder with a SKILL.md file: a name, a description of when to use it, and the steps to follow, kept in the workshop's Git repository. The agent reads the description of every skill it has and opens one only when a question needs it.

This one does three things:

  1. Gathers the morning's numbers with the agent's own tools.
  2. Lays them out with a small script.
  3. Emails the result.

Read it: SKILL.md in the repository.

Go back to Snowsight and, in the Cortex Code panel, paste this prompt. It copies the skill into a stage the agent reads from, then adds the skill and a tool that sends the email, and lets code execution, which the agent has had since Step 6, run the skill's script without asking.

Prompt 5:

cortex code
First create stage WILDERNESS_HOL.LAB1_ASSISTANT.SKILLS with a directory table, copy
@WILDERNESS_HOL.SETUP.WORKSHOP_REPO/branches/main/skills/christmas-trading-report/ into
@WILDERNESS_HOL.LAB1_ASSISTANT.SKILLS/skills/christmas-trading-report/, and refresh the stage.

Then update agent WILDERNESS_HOL.LAB1_ASSISTANT.WILDERNESS_ASSISTANT in place (ALTER AGENT ... MODIFY LIVE VERSION, keep every existing instruction, tool and sample question so it stays listed in CoWork). Add:
1. Skill christmas-trading-report, source type STAGE, path @WILDERNESS_HOL.LAB1_ASSISTANT.SKILLS/skills/christmas-trading-report
2. Set the existing code_execution tool to run without asking for approval (permission_policy always_allow), so the skill can run render_report.py.
3. A custom (generic) tool send_report_email for WILDERNESS_HOL.LAB1_ASSISTANT.SEND_REPORT_EMAIL(SUBJECT VARCHAR, HTML_BODY VARCHAR) on WILDERNESS_WH, both arguments required.

In the orchestration instructions, tell the agent to follow the christmas-trading-report skill step by step without stopping to ask the user for confirmation. Use send_report_email only in step 4 of that skill: say so in the tool description and the orchestration instructions, and refuse any other email request.

Then run DESCRIBE AGENT and SHOW AGENTS IN SNOWFLAKE INTELLIGENCE SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT to confirm.
You should see

The stage SKILLS with the skill's files in it. Then DESCRIBE AGENT shows the tool send_report_email next to the other four, one skill, christmas-trading-report, and the four sample questions still there. SHOW AGENTS IN SNOWFLAKE INTELLIGENCE still lists WILDERNESS_ASSISTANT.

In CoWork, start a new conversation with the Wilderness Assistant and ask the question below.

cowork
Prepare this morning's Christmas stock briefing for Martha and email it to me.
You should see

The thinking steps name the skill christmas-trading-report, then the retail_analyst and customer_feedback calls, a code step and send_report_email. After two to four minutes the reply ends with "Sent to" your email. The email comes from no-reply@snowflake.net, so check junk.

It has three tiles: about 5,200 tents left over on Boxing Day, 18% of the faulty batch, B26-07, returned, and 33 stores running out of tents. Below them are the stores running out, the stores with tents left over, three customer comments and three things to do this week: send the broken tents back, move the spare tents north, and reorder the rest.

It can email only you

SEND_REPORT_EMAIL takes a subject and the HTML, and no address. Setup built it to send only to the email you verified, so nothing the assistant writes can send a report anywhere else.

Steps 3 to 6: build the search, the semantic view changes and the assistant in one block

If a prompt in Steps 3 to 6 did not finish, run this in your SQL file instead.
