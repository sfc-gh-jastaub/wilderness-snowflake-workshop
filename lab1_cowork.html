Overview

What you will build

  • Run one script that builds Wilderness's data in your account: 72 stores plus online, 1,200 products, three million sales lines since July 2024 and 20,000 customer comments.
  • Ask Cortex Code to make the customer comments searchable with Cortex Search.
  • Ask it to teach the semantic view Wilderness's words: a return rate, synonyms and two answers you have checked.
  • Ask it to create the Wilderness Assistant with three tools: the numbers, the customer comments and charts.
  • Test the assistant, then have Cortex Code put it in CoWork, where the store managers work.
  • Ask it about the numbers, then the words, then both, in CoWork; save a chart and schedule a question so the sleeping-gear shortfall arrives by email.

What you use

Cortex Code Cortex Search Semantic views Cortex Analyst Cortex Agents Snowflake CoWork Artifacts Automations Agent skills

Synthetic data

Wilderness Outfitters is a fictional company. All stores, products, people, sales and feedback in this workshop are synthetic and generated for training. Any resemblance to a real business is coincidental.

1

Run one script, open Cortex Code

~6 min
Before you start: your trial account

Use the trial you created from the workshop sign-up link (AWS US West 2, Oregon), and stay in it all day. Click the verification link in the welcome email first: the automation in Step 9 and the briefing in Step 10 both email you, and an unverified address receives nothing.

The story so far: Wilderness bought 40% more tents than it sold last Christmas and sent them to every store, bought sleeping gear as usual, and some of the Summit 2P tents on the catalogue cover are coming back broken.

It is Wednesday 4 November 2026. Christmas trading started on Sunday and runs to Christmas Eve. Your team has been asked to give Martha's 72 store managers an assistant that tells them where they stand every morning. You build it in this lab by asking Cortex Code for it, one prompt at a time.

Run the setup script

  1. In Snowsight, go to Projects » Workspaces.
  2. Select + Add new » SQL File.
  3. Copy the block below, paste it into the file and select Run all.
sql
-- =====================================================================================
-- 00_bootstrap.sql  ·  Wilderness Outfitters workshop
-- The only thing you paste. It connects your account to the workshop's GitHub repo and
-- runs the rest of the setup from there.
-- =====================================================================================
USE ROLE ACCOUNTADMIN;
CREATE WAREHOUSE IF NOT EXISTS WILDERNESS_WH WAREHOUSE_SIZE = SMALL AUTO_SUSPEND = 60 AUTO_RESUME = TRUE
  INITIALLY_SUSPENDED = TRUE;
USE WAREHOUSE WILDERNESS_WH;
CREATE DATABASE IF NOT EXISTS WILDERNESS_HOL;
CREATE SCHEMA IF NOT EXISTS WILDERNESS_HOL.SETUP;

CREATE OR REPLACE API INTEGRATION WILDERNESS_GIT_API
  API_PROVIDER = git_https_api
  API_ALLOWED_PREFIXES = ('https://github.com/sfc-gh-jastaub/')
  ENABLED = TRUE;

CREATE OR REPLACE GIT REPOSITORY WILDERNESS_HOL.SETUP.WORKSHOP_REPO
  API_INTEGRATION = WILDERNESS_GIT_API
  ORIGIN = 'https://github.com/sfc-gh-jastaub/wilderness-snowflake-workshop.git';

-- Core setup, about 2 minutes: infrastructure, data, feedback, semantic view, Lab 3 assets
EXECUTE IMMEDIATE FROM @WILDERNESS_HOL.SETUP.WORKSHOP_REPO/branches/main/setup/10_setup_core.sql;

SELECT STEP, STATUS, ROWS_AFFECTED, LOGGED_AT FROM WILDERNESS_HOL.SETUP.SETUP_LOG ORDER BY LOGGED_AT;

-- Your link to open the workshop repo as a workspace, with the form already filled in
SELECT 'https://app.snowflake.com/' || LOWER(CURRENT_ORGANIZATION_NAME()) || '/' || LOWER(CURRENT_ACCOUNT_NAME())
    || '/#/workspaces?action=create_workspace_from_git_repo'
    || '&remoteUrl=https%3A%2F%2Fgithub.com%2Fsfc-gh-jastaub%2Fwilderness-snowflake-workshop'
    || '&workspaceName=wilderness-snowflake-workshop&apiIntegration=WILDERNESS_GIT_API&authType=NONE'
    AS OPEN_WORKSHOP_REPO;
What the script builds

It connects your account to the workshop's GitHub repository and runs the rest of the setup from there: sales since July 2024 for 72 stores and online, 20,000 customer comments, and a starter semantic view over sales, returns and stock. It all runs on one small warehouse that suspends after a minute. It takes about two minutes.

You should see

The setup log, with every step OK, and a last result with one link, OPEN_WORKSHOP_REPO. You use the link in Lab 2.

If a step shows something other than OK

EMAIL shows NO_EMAIL_ON_USER when your Snowflake user has no email address. Add one under your name » Settings, then select Run all again. Running the script twice is safe: it replaces what it built and leaves the same data.

Open Cortex Code

Cortex Code is an agent in Snowsight that writes and runs SQL for you, in your account, with your rights. You say what you want; it works out how, runs it and shows you the result. Every build step in this lab is one prompt to it.

  1. In the same Workspace, open the Cortex Code panel.
  2. Paste the prompt below and send it.
  3. The first time Cortex Code asks to run a statement, choose Always allow, so it runs each one without asking again.
cortex code
I'm working in Snowflake database WILDERNESS_HOL with warehouse WILDERNESS_WH, for Wilderness Outfitters, an Australian outdoor retailer. The data is in schema RAW. Create everything I ask for in schema LAB1_ASSISTANT. For this whole session: run each statement rather than drafting it, use fully qualified names, and after you create anything, show me proof that it exists.
You should see

Cortex Code confirms the database, warehouse and schemas, and may run a quick query to check it can see WILDERNESS_HOL.

2

Make customer feedback searchable

~5 min
What Cortex Search is

It makes text searchable by meaning, not just by matching words. "The pole snapped at the hub" and "broken frame" come back for the same question. You point it at a column of text; Snowflake builds and refreshes the index for you.

Twenty thousand customer comments sit in one table: product reviews, notes from the returns desk and survey answers. Ask Cortex Code to make them searchable.

cortex code
Make the customer comments in WILDERNESS_HOL.RAW.CUSTOMER_FEEDBACK searchable. Create a Cortex Search service called CSS_CUSTOMER_FEEDBACK on the FEEDBACK_TEXT column, with the product, category, tent batch, store, state, rating and feedback source as attributes so they can be used as filters, refreshed daily. Then search it for comments about Summit 2P tent poles and show me the top three.
You should see

The CREATE CORTEX SEARCH SERVICE statement Cortex Code wrote and ran, then three comments about Summit 2P poles snapping or bending, quoted word for word. It takes about a minute to build the index.

Why the attributes

They let a search filter while it matches meaning: "pole complaints in Victoria about one batch of tents" needs both. Ask Cortex Code to explain it in its own words if you want to hear it a second way.

3

Teach the semantic view Wilderness's words

~8 min
What a semantic view is

It describes structured data, the tables of sales, returns and stock, in Wilderness's terms: what a sale is, how a return links to a sale, what "return rate" means. An agent reads it to turn a question into the right query.

Setup created a starter semantic view, SV_WILDERNESS_RETAIL, over sales, returns, stock and the sleeping gear each store needs. It knows the tables and how they join, but not how store managers talk. Ask Cortex Code to teach it.

cortex code
Improve the semantic view WILDERNESS_HOL.LAB1_ASSISTANT.SV_WILDERNESS_RETAIL so store managers' words work. Add a RETURN_RATE metric: units returned divided by units sold. Add synonyms for the words they use: tent, sleeping gear, Christmas range, returns and stock cover. Add two verified queries: the return rate by category, and the sleeping-gear shortfall by state. Keep everything else as it is. Show me what you will change before you apply it, then list the view's metrics and verified queries.
You should see

Cortex Code shows the changes first, then applies them. The view now lists RETURN_RATE among its metrics and two verified queries. Its wording for the synonyms and the queries will differ from your neighbour's.

Read what it wrote

Open the view in AI & ML » Cortex Analyst and read the metric and the verified queries. This file is where a team's knowledge of its own data lives, and it decides how often the assistant is right. A verified query is a question with SQL you have checked: when someone asks something similar, Cortex Analyst starts from it.

4

Create the Wilderness Assistant

~8 min
What an agent is

It answers a question by choosing tools and putting the results together. Here it has three: Cortex Analyst for numbers, through the semantic view; Cortex Search for what customers said; and Data to Chart, which turns a result into a chart. Its instructions tell it who it is talking to and how to answer.

One prompt creates the agent and gives it all three tools.

cortex code
Create a Cortex Agent called WILDERNESS_ASSISTANT in WILDERNESS_HOL.LAB1_ASSISTANT, with the display name Wilderness Assistant, for Wilderness's 72 store managers. Give it three tools: a Cortex Analyst tool called retail_analyst on the semantic view SV_WILDERNESS_RETAIL, a Cortex Search tool called customer_feedback on CSS_CUSTOMER_FEEDBACK, and the Data to Chart tool (type data_to_chart) called data_to_chart, so it can draw charts. Use warehouse WILDERNESS_WH. Write its instructions: plain Australian English, short sentences, amounts in AUD, the answer first, and say plainly when the data cannot answer something. Add three sample questions: one about the numbers, one about what customers say, and one that needs both. Then show me the instructions and the tool descriptions you wrote.
You should see

The agent created with three tools, retail_analyst, customer_feedback and data_to_chart, then the instructions and tool descriptions Cortex Code wrote for it. It also appears in AI & ML » Agents as "Wilderness Assistant".

Read the tool descriptions

The agent reads each tool's description to decide which one to use. "Sales, returns and stock numbers" and "what customers said" is all it takes to route a question to the right place. When an agent picks the wrong tool, this is the first thing to fix.

Stuck? Build Steps 2 to 6 in one block

If a prompt in Steps 2 to 4 did not finish, run this in your SQL file instead. It builds the feedback search, the semantic view changes and the Wilderness Assistant in LAB1_ASSISTANT, and adds the assistant to CoWork, so you can carry on from Step 5. It takes about a minute, and running it again replaces what it built.

Publish it to CoWork

~4 min

Store managers will not open Snowsight. They use CoWork, the chat app at ai.snowflake.com, which lists only the agents an administrator adds to it.

cortex code
Add the Wilderness Assistant agent to CoWork so the store managers can use it, and show me that it is listed.
You should see

One statement that adds the agent to the account's CoWork, and a list that includes WILDERNESS_ASSISTANT.

"The store managers can't use it yet"

Cortex Code may add that store managers need a role with access to the agent and its tools. That is right, and you do not need it today: you sign in as ACCOUNTADMIN, so the agent is yours to use in CoWork straight away. The technical track builds the store-manager role in Lab 3.

CoWork in SQL

SQL still uses CoWork's earlier name, so the statement says SNOWFLAKE INTELLIGENCE and the account's CoWork object is SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT. You will see both in what Cortex Code ran.

7

Numbers, words, then both

~8 min

Now use it the way a store manager will.

  1. Open ai.snowflake.com in a new tab and sign in with the same account.
  2. Choose Wilderness Assistant and ask the questions below, in order, in one conversation: the numbers, then the words, then both.

The numbers, from the semantic view:

cowork
Tents are our big Christmas bet. Where will we still be holding tents on Boxing Day, and where will we run out?

What customers say, from the search service:

cowork
What are customers saying about the Summit 2P tent?

Both together. This is the question no report or chatbot answers on its own:

cowork
Customers are bringing the Summit 2P back. What are they saying, and is it worse for some batches than others? Chart the return rate by batch.
You should see

First, tents left over in Victoria and Tasmania and tents running out in New South Wales and Queensland. Second, comments quoted word for word about poles snapping at the hub and seams leaking. Third, both tools in the thinking steps, batch B26-07 coming back at about 17% against about 4% for the other batches, and a chart.

Keep this conversation open

You save the chart in Step 8.

8

Keep the answer: artifacts

~5 min

A chat answer disappears into the history. An artifact keeps it: a saved chart that reruns its query when you open it.

  1. On the return-rate chart from Step 7, select Save.
  2. Open the Artifacts hub, then Saved, and open the chart.
You should see

The chart in your saved artifacts, with the date it last ran.

  • The chart reruns its SQL when you refresh it, with your own access rights.
  • A question like "last 30 days" moves forward each time. Fixed dates stay fixed.
  • A shared conversation is different: it is a snapshot and never reruns.
9

Schedule it: automations

~6 min

This is where the sleeping-gear problem first reaches the people who can act on it. An automation asks a question again on a schedule and emails the answer, so every morning the stores short of sleeping gear land in the store manager's inbox, in time to reorder by 13 November, without anyone remembering to ask.

  1. In the same conversation, ask the question below.
  2. Confirm the schedule CoWork proposes.
  3. Open the Automations tab to see it with its next run time.
  4. Open the automation and select Run now, so you do not have to wait for the hour.
cowork
Send me the sleeping-gear shortfall by store every hour.
You should see

One automation marked Active with a next run time within the hour. A few minutes after Run now, an email with the sleeping-gear shortfall by store arrives at the address you verified. It also appears in the automation's run history.

It runs every hour until you change it

Each run re-asks the question as you, against the latest data, on your warehouse. Hourly is for today, so you see it work. In Lab 3 you count what it costs and move it to weekdays at 7am, the schedule a store manager would use. Cleanup deletes it.

10

Brief Martha: a skill that emails a report Optional

~10 min

The automation sends a summary, worded however the assistant likes that day. A skill makes Martha's briefing the same shape every time: a set of instructions in plain English, with a small script, kept in the workshop's Git repository. Any agent that references it can use it.

What a skill is

A folder with a SKILL.md file: a name, a description of when to use it, and the steps to follow. The agent reads the description of every skill it has and opens one only when a question needs it. This one gathers the morning's numbers with the agent's own tools, lays them out with a script, and emails the result. Read it: SKILL.md in the repository.

Back in Cortex Code, one prompt adds the skill and the two things it needs: code execution for its script, and a tool that sends the email.

cortex code
Add the skill at @WILDERNESS_HOL.SETUP.WORKSHOP_REPO/branches/main/skills/christmas-trading-report to the agent WILDERNESS_HOL.LAB1_ASSISTANT.WILDERNESS_ASSISTANT. Also give the agent the code execution tool, and a custom tool called send_report_email for the procedure WILDERNESS_HOL.LAB1_ASSISTANT.SEND_REPORT_EMAIL on warehouse WILDERNESS_WH, described as: Emails a finished HTML briefing to the person asking. Call only from the christmas-trading-report skill. Add to its orchestration instructions: use the christmas-trading-report skill only when the user asks for a briefing or report to be sent, and never call send_report_email outside that skill. Keep everything else as it is, then show me the agent's tools and skills.
You should see

The agent's tools now include code_execution and send_report_email next to the other three, and one skill, christmas-trading-report.

It can email only you

SEND_REPORT_EMAIL takes a subject and the HTML, and no address. Setup built it to send only to the email you verified, so nothing the assistant writes can send a report anywhere else.

In CoWork, start a new conversation with the Wilderness Assistant and ask:

cowork
Prepare this morning's Christmas stock briefing for Martha and email it to me.

When CoWork asks whether it may run code, allow it.

You should see

The thinking steps name the skill christmas-trading-report, then the retail_analyst and customer_feedback calls, a code step and send_report_email. After two to four minutes the reply ends with "Sent to" your email. The email comes from no-reply@snowflake.net, so check junk: three tiles (about AUD 898,000 of tents left over on Boxing Day, the 17.2% return rate on the faulty batch, B26-07, and 31 stores short of sleeping gear), the tents, the sleeping gear, three customer comments and three things to do this week.
